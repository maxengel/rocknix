# #135 Time to play is a first-class metric: no sync may stand between the player and a game [OPEN]

**Maintainer, 2026-09-11:** "we need to think about a key metric being the time to play, meaning how long does it take for someone to go from being in the UI to starting a game, or from exiting a game to starting another game. Things that could slow this down, for example, are: startup; game save sync when the console starts syncing after exiting a game, when you're then unable (or should be unable) to start a new game until the saves are written to the cloud, etc. We need to balance our goal of having a rigorous backup and sync engine with a player's goal of wanting to actually enjoy playing a game as quickly as possible."

Decision D-CLOUD-098. What already holds: a launch cancels an automatic sync in any phase (D-CLOUD-076); a sync that can touch saves gates a launch (D-CLOUD-038), which is the tension to measure rather than assume.

## The metric

- **UI → game**: from the press on a game to the emulator's first frame, on a device with cloud sync on, at boot (startup sync running) and at rest.
- **Game → game**: from the exit hotkey to the next game's first frame, with the exit sync in flight.
- Budgets to propose after a first measurement; the exit sync of one changed save should not add more than the network round trip it needs, and never a wait the player can see without a card saying why.

Can this be done on the VM? **Yes** -- `tools/vm-qa` gets a `time-to-play` cell: boot the pair, time carousel → RetroArch first frame (the exit test already detects the process; a frame is the screendump changing), and exit → relaunch with the exit sync running against the QA endpoint, with and without a bandwidth cap. Reported in the runner's table on every image.

## Acceptance criteria

- [ ] The runner reports both times for every image, and `docs/vm-qa-log.md` carries them.
- [ ] A budget for each is a register row, and a run over budget fails the suite.
- [ ] The design of #134's history store and #22's reconciler is checked against the budget before it lands (retain-before-publish is one extra small transfer; it must not be on the launch path).
- [ ] Settings that trade rigour for speed (startup sync, exit sync) say what they cost in seconds where the player turns them on.
