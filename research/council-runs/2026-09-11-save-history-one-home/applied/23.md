**What changed.** The wizard is opened by the player from a badge, never over them by an unattended pass (D-CLOUD-035). *Keep earlier versions of saves* is **on by default** with a count (D-CLOUD-032/036), and there is **no undo control** in the flow (D-CLOUD-033). An unexplained absence is a question on the same compare surface (D-CLOUD-037). The discarded copies live in the cloud, in the history store `<SAVES_REMOTE>/.history/` (D-CLOUD-095, #134), so the done page says so. "Nothing transfers until COMPLETE" becomes "**no resolution applies until COMPLETE; the pre-pass is not rolled back**". Auto states get a rule, not a question. Rows are two lines (D-UI-023). **Conflict resolution assumes serial play** (D-CLOUD-103): the two versions were made in sequence by one person -- the realistic case is a commute session that never synced meeting an evening session at home -- so the page names which session was later and opens with the cursor on it (D-CLOUD-104), and KEEP BOTH is a first-class answer rather than an edge case. The IA is `docs/conflict-wizard-ia.md`, to be revised to rev 5 as listed in #134.

### The entry (D-CLOUD-035, D-UI-023)

In `GAME SETTINGS > CLOUD SETTINGS`, one row:

```
MANAGE GAME SAVE RESTORES AND CONFLICTS
3 waiting                                  <- or: Nothing waiting
```

The count appears as a badge glyph with the number on the CLOUD SETTINGS entry and on the card's outcome line (`DONE - 3 WAITING FOR YOU`). In V1 the page inside holds the queue; #25 adds the history view to the same page so the player learns one place.

### The walkthrough

- Header is the count (`3 CONFLICTS FOUND`); system by system, then game by game; **CLOUD always left**, THIS DEVICE right (D-CLOUD-041, D-CLOUD-104); source badge over the picture; save states show the screenshot, game saves a glyph, never a substitute image.
- Metadata per side: date - time (local, with the offset; `clock_synced: false` shown as *time not trusted*) - device label - core + build pin (or emulator + version). No file size, no play time. `unknown` renders as `unknown`.
- **Which session was later** (D-CLOUD-103/104): under each column, one line ordered by **publish sequence, never by clock** -- *PLAYED LATER ON <DEVICE NAME>* / *PLAYED EARLIER ON <DEVICE NAME>*, the name being the one the player gave that console (D-NET-001), which the metadata line already carries as the device label. The sequence is causal (each version's `<seq>` and manifest entry say which device published it and after which agreement), so it is truthful where a clock is not. The page **opens with the cursor on the newer version**, whichever column it is in, so the common resolution of a missed sync is one press; nothing is kept without that press and the other version is retained (D-CLOUD-032). The exact words of the two lines are a proposal, like the labels in P-11.
- Choices **KEEP LEFT / KEEP RIGHT / KEEP BOTH**; the chosen column highlights. KEEP BOTH is dimmed with a reason for game saves and for any unit not launched by RetroArch (`SaveStateRepository::isEnabled`, `SaveStateRepository.cpp`). Reserved slots are shown when KEEP BOTH is chosen: `Merged copy goes to slot 4`.
- **The auto rule**: a divergent `.state.auto` pair shows one sentence -- `This device keeps its resume point; the cloud's is kept as slot 4.` -- and asks nothing (#24). Gate 12 measures how often this fires and how many slots it adds; that cost is recorded before the IA is finalised.
- **The absence question** (D-CLOUD-037), on the same surface with one side empty:

  ```
  THIS SAVE IS GONE FROM THIS DEVICE
  ( BRING IT BACK )  ( REMOVE IT EVERYWHERE )
  ```
  and its mirror, `THIS SAVE IS GONE FROM THE CLOUD` -- `( PUT IT BACK IN THE CLOUD ) ( REMOVE IT FROM THIS DEVICE )`. Either removal is a wizard decision and its copy is retained. The mass case never reaches this page (#22 refuses the pass).
- The last CONTINUE is **COMPLETE**. At COMPLETE the adapter re-checks local members, the cloud head by a fresh listing, the unit map, reserved slots and pending retirements; a mismatch re-opens that conflict rather than applying a stale plan.
- **The apply step.** Every decision applies through the reconciler, and the displaced version is in the store before anything is replaced (#22 R9): KEEP LEFT uploads this device's loser into `.history/` as `discarded`, verifies it, then installs the cloud copy here; KEEP RIGHT copies the cloud loser into `.history/` as `discarded` -- server-side, verified, **never a move** (P-3) -- and only then writes this device's version as the cloud's current save; KEEP BOTH retains nothing; either answer to the absence question places the removed copy as `deleted` before the removal. The winner is never written into the store: it holds displaced versions only. Each discard's audit line is written before anything is replaced (D-CLOUD-027).
- Quitting discards the decisions and applies nothing; the pre-pass (cloud-only fetched, device-only pushed) has already happened and is not undone.
- **Review decisions before applying** stays, off by default.

### Retention settings (D-CLOUD-032, D-CLOUD-036, D-CLOUD-096, D-UI-039)

Under `MANAGE CLOUD STORAGE > SAVE MANAGEMENT`, one row opens a page:

```
MANAGE EARLIER VERSIONS OF SAVES           <- label is the maintainer's word (P-11); this is the proposal
```

Inside, two rows and nothing else:

```
KEEP EARLIER VERSIONS OF SAVES            [ON]
ON EVERY HANDHELD THAT USES THIS CLOUD FOLDER

VERSIONS KEPT PER SAVE                    [3]      (1-9; dimmed while the switch is off)
```

Both rows show the **effective fleet value** -- the value the last pass adopted (`history_keep` in the own manifest, highest `rev`; ties ON and the larger count; #22 R9, P-1). An edit applies on this device at once and reaches the other devices at their next pass; under serial use no two edits race. The age and size caps are ours and are not rows (D-CLOUD-096, D-UI-039). This one setting covers discarded saves, replaced saves, deleted saves and suspect saves alike; the wizard has no separate switch.

**Confirmation dialogs** (where the row's explanation lives, D-UI-023):

- Turning OFF: *EARLIER VERSIONS OF YOUR SAVES WILL NO LONGER BE KEPT, ON EVERY HANDHELD THAT USES THIS CLOUD FOLDER. IF A SYNC REPLACES A SAVE BY MISTAKE, THERE WILL BE NO EARLIER VERSION TO PUT BACK. VERSIONS ALREADY KEPT STAY UNTIL THEY EXPIRE.* -- TURN OFF / KEEP ON
- Turning ON: *KEEPING EARLIER VERSIONS ADDS ABOUT N SECONDS TO THE SYNC AFTER A GAME.* -- N is filled from #135's measurement (E12), never chosen; until that runs the string is not shipped.
- COMPLETE (unchanged sentence): *Discarded saves are kept in the cloud, 3 per save.*

### The done page

Per game, two lines:

```
Advance Wars (USA) (Rev 1) - gba
Kept the cloud copy - Discarded this device's game save
```

Footer: `Discarded saves are kept in the cloud.` (or `Discarded saves were not kept.` when the switch is off). No control to put one back (D-CLOUD-033); the page outlives the apply step (`.claude/rules/es-native-ui.md`, the fourth tier). Each discard's audit line (`/storage/.cache/log/cloud_audit.log`, D-CLOUD-027) is written before the winner replaces anything.
