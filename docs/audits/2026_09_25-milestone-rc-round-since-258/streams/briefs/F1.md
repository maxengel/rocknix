## PL-033: Printing the QEMU arguments unlinks the socket paths (and, with the disk passed as `--monitor`, the disk)

- **Owner area:** tools/generic-x64-vm

- **What:** A read-only verb runs the cleanup of a start. Fix: `qemu-args` touches nothing.
- **Acceptance:** `generic-x64-vm qemu-args` on a running guest's paths leaves them
<details><summary>The audit's verdict(s) this item rests on</summary>
### F-VM-01 (gpt, 7-generic-x64-vm) -- printing the QEMU arguments unlinks the socket paths
**Checked:** `generic-x64-vm:161` (`serial.unlink(missing_ok=True)`) and `:202` (`monitor.unlink(missing_ok=True)`) run inside `qemu_command()`, which `main()` calls for `qemu-args` as for `run`. The disk-deletion input (`qemu-args D --monitor D`) is self-inflicted; the realistic harm is printing the arguments for a running guest and unlinking its live monitor and serial sockets, which the harness drives guests through.
**Verdict:** survived at **Medium**, not Critical (a fork-only QA tool; the practical case is a broken guest session, not a lost disk): construct the command without side effects and unlink at run time only.
### F-VM-01 / F-VM-02 (claude, 7-generic-x64-vm) -- the in-place bootloader updater copies an unpatched `ldlinux.sys` and the image's cfg templates over the installed ones
**Checked on guest d, 00:02 UTC:** `/usr/share/bootloader/` in the running SYSTEM holds `update.sh` and nothing else -- no `ldlinux.sys`, no `syslinux.cfg`, no `grub.cfg`, no `bootx64.efi` -- so every `[ -f "$BL/$f" ] && cp` in `update.sh:17-27` is false and the script copies nothing; `/flash` still carries the files the image writer installed (`ldlinux.sys`, `syslinux.cfg`, `EFI/BOOT/{bootx64.efi,grub.cfg,ldlinux.e64}`, both cfgs with `boot=LABEL=ROCKNIX disk=LABEL=STORAGE`), which is why `tools/vm-upgrade-rehearsal` boots after every in-place update (20 of 20 on 2026-09-20). **Refuted as a hazard; Low as a no-op**: the updater updates no bootloader at all, and still writes `UPDATE` to `/storage/.boot.hint` (the gpt seat's F-VM-02, "failures fall through to a success marker", is the same no-op seen from the other side). The seat could not see the image's contents, and said so. Punch item: either ship the files the script expects and install syslinux properly (`syslinux --install`, `extlinux`), or delete the script and the hint.
</details>
