## PL-024: A settings-lock timeout is followed by the read-modify-write anyway
- **Severity:** High
- **Category:** Guards fail closed
- **Source Finding:** F-ES-02 (gpt, 8b)
- **Owner area:** EmulationStation SystemConf
- **Where:** es-core/src/SystemConf.cpp:195-199
- **What:** After five seconds without the lock the interface saves its stale snapshot over whatever the script wrote. Fix: on timeout, re-read the file and apply only this save's dirty keys (`changedConf`), or refuse and log; never the whole snapshot.
- **Acceptance:** a unit test with the lock held by another process: the interface's save keeps a key the other writer changed; `es-syntax-check` PASS
<details><summary>The audit's verdict(s) this item rests on</summary>
### F-ES-02 (gpt, 8b-es-core) -- a lock timeout is followed by the write anyway
**Checked:** `SystemConf.cpp:195-199`: `if (!lock.acquire(5000)) LOG(LogWarning) << "... saving without it"`, then the read-modify-write proceeds unconditionally, so a script that held the settings lock for five seconds (`set_setting` under `wait_lock`) has its change overwritten by the interface's stale snapshot. The choice is deliberate -- an interface that never blocks on a stuck script -- and it is the shape `engineering-practices.md` § Guards must fail closed forbids. **Survived, High** (Critical as filed; the other writer must be stuck for five seconds). Fix: after the timeout, re-read the file and apply only this save's dirty keys (`changedConf` exists for that), or refuse and say so.
### F-ES-02 (gpt, 8a-es-app) -- the hub's gated rows keep offering setup after setup completes
**Checked:** the gated rows decide `configured` when the hub is built (`cloudAddGatedEntry`, `:4010`, `:5853`); `openCloudAddRemote` (`:7293-7303`) presents the wizard's first page with `prev = nullptr`, so the hub stays on the stack, and CLOUD SETUP COMPLETE's FINISH is `s->close()` (`:6463`) -- the player lands back on the hub they left, whose rows still open the setup offer until the page is reopened. **Survived, Medium** (High as filed; one back-and-forth fixes it). Fix: FINISH reopens the hub (`openCloud(window)` after closing it), or the gated callback re-checks `exists(rclone.conf, false)` at the press.
</details>
