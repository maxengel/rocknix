## 0. Three facts that shape the design

1. **Deterministic kill points exist for shell writers, in two forms.** (a) *Step shim*: a `--path-prefix` directory already goes first on PATH for every command (`Device.run`), and `cloud_capture`, `cloud_device_id`, `cloud_saves_root`, `cloud_content_*` never source `/etc/profile`, so a shim named `mv`/`cp`/`mkdir` that does its half-step and then `kill -KILL -- -<pgid>` lands the kill at an exact boundary (CAP1/CAP10/CAP11 already stage shims this way). It does **not** work for `backuptool` or `set_setting`: `/etc/profile` prepends `/usr/bin` (`001-functions:8`), so for those the harness defines a *bash function* of the same name in the calling shell (functions beat PATH), or uses (b) a *guest-side watcher*: a tiny uploaded script (a file, per the `pkill` self-match lesson) that polls a filesystem marker every 20 ms and kills the group — for long-running binaries (`tar`, `rclone`, `cp` of a 64 MiB state) whose window is seconds. Both reuse `Link.start()`'s detached `setsid nohup sh -c` and its `pid` file, and `finish_or_kill`'s `kill -- -pgid`.
2. **A power cut is one HMP command.** `generic-x64-vm` always starts `-monitor unix:<sock>,server,nowait` (`/tmp/rocknix-qemu-monitor.sock`; `-b` suffix for pair guest b). `system_reset` drops every dirty page in the guest and keeps QEMU up, so no relaunch is needed; the drive has no `cache=` (default writeback) so the disk holds exactly what the guest issued. It models a battery dying; it cannot model an SD card's write cache or FTL (the RG SP's), which the report states as "what the VM cannot prove".
3. **The two ES config writers are the un-fixable-by-harness part.** `Settings::saveFile` (`es-core/src/Settings.cpp:498`) is pugixml `save_file` = `fopen("wb")`: truncate the live file, write, no fsync, no rename. `SystemConf::saveSystemConf` (`SystemConf.cpp:188-206`) writes `system.cfg.tmp` and then **copies** it into `system.cfg` with a truncating `ofstream` — the tmp is never renamed into place, so it buys nothing. The torn-write window is microseconds; no external kill lands in it deterministically. So the config cells have two arms: a writer arm that is a repeated smoke test with an invariant, and a reader arm with **planted** torn files, which is where the rule is actually proven (and where `chksysconfig` fails it today, §6).

## 1. The cells

Pre-state always includes a *previous* version so "previous intact" can fail. Every cell ends with `litter_scan()` and `assert_message()` (§2).

## 2. The two helpers

### 2a. `assert_message(out, rc)` — the vocabulary gate

What "player-visible" means today, from the classifiers: the **card** (`ThreadedCloudSync.cpp:~118-135`) shows a script line iff it has `%`, ` / `, or `ERROR|FAILED|WARN` (case-folded) and is not a `>>> ` protocol line; the **page** (`GuiCloudTransfer::handleLine`) shows only `>>> ` markers and rclone lines (`Transferred:`, `Checks:`, ` * name: NN%`) — script prose never reaches it. So the assertion checks two things per run:

```python
PROTO   = re.compile(r"^>>> ")
RCLONE  = re.compile(r"^(Transferred:|Checks:|Elapsed time:|Errors:|Deleted:|Renamed:|Transferring:|Checking:)|^\s*\*\s")
DECOR   = re.compile(r"^[=\-]{4,}$|^\s*$")
ANSI    = re.compile(r"\x1b\[[0-9;]*m")

def card_visible(out):      # exactly the card's predicate
    for raw in out.splitlines():
        s = ANSI.sub("", "".join(c for c in raw if 32 <= ord(c) < 127)).strip()
        if not s or PROTO.match(s): continue
        u = s.upper()
        if "%" in s or " / " in s or any(w in u for w in ("ERROR", "FAILED", "WARN")):
            yield s

def last_player_line(out):  # what #105 will make the outcome line
    lines = [ANSI.sub("", l).strip() for l in out.splitlines()]
    lines = [l for l in lines if not (PROTO.match(l) or RCLONE.match(l) or DECOR.match(l))]
    return lines[-1] if lines else ""

# Developer words a handheld's screen must never carry. Each alternative names
# a fragment seen in the scripts today (§6): exit codes, rc=, log paths, logger,
# rclone, CLI flags and script names as "recovery" instructions, signals, sysexits.
FORBIDDEN = re.compile(
    r"(?i)(\bexit(ed)?(\s+code)?\s*[:=]?\s*\(?-?\d+\)?|\brc\s*=\s*-?\d+|/var/log\S*|\S+\.log\b"
    r"|\blogger\b|\bjournalctl\b|\brclone\b|\bstderr\b|\bsysexits\b|\bEX_[A-Z]+\b|\bSIG(TERM|KILL|INT)\b"
    r"|\berrno\b|\bpid\s+\d+|\bflock\b|\bsentinel\b|\bcloud_[a-z_]+\b|\bbackuptool\b|(^|\s)--[a-z][a-z-]+"
    r"|\bCOMPLETED WITH ERRORS\b)")

# The positive shape, to be pinned once #105's first checkbox is decided:
ALLOWED_SURFACE = re.compile(r"^(COMPLETED( WITH GAPS)?|COULDN'T FINISH|SKIPPED)( - [A-Z0-9 ,.'-]+)?$")
ALLOWED_SCRIPT  = re.compile(r"^(Completed( with gaps)?|Couldn't finish|Skipped)\b.*[.!]$")
RECOVERY        = re.compile(r"(?i)\btry again\b|\bwhen you'?re (back )?online\b")
```

Rules: every `card_visible` line and the `last_player_line` must not match `FORBIDDEN`; the last line must match `ALLOWED_SCRIPT`; when `rc not in (0, 75, 69)` the last line must also match `RECOVERY`; and the `last-*` stamp's second field must equal `rc` (LINK's `stamps()` check, generalised). The `ALLOWED_*` regexes are placeholders until the vocabulary is written into `es-native-ui.md`; land `FORBIDDEN` first — it already fails, correctly, on today's `Log file: /var/log/cloud_sync.log` (the last line of every `cloud_backup`/`cloud_restore` run), `Backup of nes failed (rclone exit 3).` (`cloud_content_backup:496`), `Restore reported errors. Check 'logger' output…` (`backuptool:251`), and `cloud_saves_root`'s `run: cloud_setup --accept-saves-root`. Apply it to the existing failure fixtures too: run_steps' lock (`/tmp/second.out`) and no-network steps, A9's refusals, A12, every LINK cell (its detached `out` file) — one call in `Link.exercise` after `keep()`, one in `run_rc`'s callers that assert a failure.

The page side cannot be read by the harness; the proxy is `rc` + the script's stdout (which is all the page and card have), and `tools/vm-visual-qa` frames at 1280×800 and 640×480 remain #105's last checkbox.

## 3. What the proposed `.last-good` behaviour is tested as (KILL12/13, arm B)

Assert these as the contract of #104's config-file box, so the fixtures are written before the fix and fail against `next`:

3. **Shutdown hook** (`save-sysconfig.service`): refreshes `.last-good` only from a file that validates; an invalid live file at shutdown is *restored from* `.last-good`, not copied over it.
4. ## 4. The power-cut cell in detail (KILL13)

Prerequisites: a headless guest (`generic-x64-vm run --headless --daemonize`) so the harness has SSH (10022), serial (`/tmp/rocknix-qemu-serial.sock`) and the monitor (`/tmp/rocknix-qemu-monitor.sock`, new `--monitor-socket` flag, `-b` variants from `vm-pair` for guest b). `Link.assert_same_guest` runs first (a nonce over SSH read over serial), and a second nonce check for the monitor: `sendkey` nothing — instead `info name`/`info status` is not identifying, so the monitor is proven by *effect*: after `system_reset`, serial must see `/proc/uptime` fall. `Monitor` is a 40-line HMP client (connect AF_UNIX, read the `(qemu)` prompt, send `system_reset\n`, read the prompt back); `tools/vm-visual-qa` already speaks HMP for `sendkey`/`screendump` and is reused for the key walk.

**Setup.** Snapshot `es_settings.cfg`, `system.cfg`, `.backup` (put back in `finally`, then `systemctl restart emustation` — ES holds settings in memory and would rewrite the restored file on its next save). Plant a non-default S0 in both files (`ScreenSaverTime` odd value; `system.qa.marker=1` via `set_setting`), `systemctl restart emustation`, send one `z` and read a frame (a restarted ES lands on the last game list, not the carousel — the doc's gotcha). Read `sha256` of both files.

**Arm A — the writer, N trials (default 3, `--power-cut-trials`).** Walk (a `tools/vm-walks/ui-settings-toggle.steps` to be written and *read by frames* before it is trusted): `shift` (wake), `ret` (menu), to UI SETTINGS, `x` on a `Settings`-backed switch (e.g. SHOW CLOCK); then `dev.disconnect()` (a ControlMaster across a reset stalls exactly as it does across a link cut); then on **one** monitor connection `sendkey z` (closes the page → `GuiSettings::save()` → `Settings::saveFile()` **and** `SystemConf::saveSystemConf()`) followed by `system_reset` after a gap from the ladder `{0, 50, 200, 1000} ms`, plus one control trial with `vm-serial sh sync` between the close and the reset, and one with no change at all. Wait for boot over serial: `cut -d' ' -f1 /proc/uptime` < 60 **and** `pgrep emulationstation | wc -l` = 1 (`vm-serial wait` alone returns at once while the old ES is still up), then LINK's `NETOK` test, then SSH reconnects on a fresh master. Assert per trial, per file: parses; equals S0 or S0+toggle (compare parsed dicts, not bytes); size > 0; not equal to `/usr/config`'s default dict; no `system.cfg.tmp`; and — since `/var/log` survives until the next boot — `es_log.txt` has no `Could not parse Settings file`. ## 5. How KILL fits the harness

- **Registry**: `KILL_FIXTURES = [(key, title, fn, needs)]` with `needs ⊆ {"backend", "minio", "serial", "monitor"}`; `list_fixtures` prints the needs column; `run_kill` skips a cell whose channel is missing *with a line* (as `main` does for LINK) rather than the set. `--kill` runs them after the suite; `--only KILL1,...` runs a subset; cells with `needs == {}` (KILL3/4/6–11/14–16/18) are grouped as `kill_local_keys` so an `--only` naming only those prepares locally (`prepare_local`, like `cap_only`) and needs no MinIO or WebDAV.
- **Class**: `class Kill(Link)` — inherits `start/status/wait_marker/rc_line/fingerprint/settle/endpoint_quiet/stamps/keep/reset`; adds `kill_group(sig, wait=2.0)` (D-CLOUD-076's TERM→KILL ladder is a mode), `watch_then_kill(marker_glob, sig)` (uploads `/tmp/qa-kill/watch.sh` once; polls every 20 ms; the harness asserts the kill *landed* — "the run ended before the kill could land" is a setup FAIL, LINK's pattern), `shim(name, body)` (a per-cell dir prepended to `dev.path_prefix`; refuses for `backuptool`/`set_setting` and uses the function-override form there), `Monitor`, `reboot_wait()`. Cache and config snapshots as `run_link` does (`snapshot_cache/restore_cache`), plus `system.cfg{,.backup,.last-good}` and `es_settings.cfg{,.last-good}` for KILL12/13, restored in `finally` with an ES restart.
- **Flags**: `--kill`, `--monitor-socket` (default `/tmp/rocknix-qemu-monitor.sock`), `--power-cut-trials` (3), `--cut-after-ms` (`0,50,200,1000`). `--dump` keeps each cell's `out/rc/pid/rerun.out` under `<dump>/KILLn/` via `keep()`.
- **Backends**: KILL1, KILL5 run on WebDAV and again on MinIO (`CLOUD_QA_BACKEND=s3`), because the receiving-side semantics differ (the QA WebDAV store preallocates the final name and holds a stale-PUT lock; S3 commits a PUT atomically and leaves nothing) — the same "once on WebDAV and once on MinIO" the pair fixtures already prescribe. KILL2, KILL17 WebDAV only; the rest need no endpoint.
- **Runtime** on KVM: KILL1/2/5 ~60–90 s each (throttled transfer + settle + re-run); KILL3/4 ~20 s; KILL6–11, 14–16, 18 ~5–15 s; KILL12 ~5 min; KILL13 ~6 min. Whole set ≈ 15–18 min on WebDAV, +4 min for the MinIO pass. Serial/monitor required only by KILL12/13.
- **Docs**: one paragraph in `generic-x64-vm-testing.md` beside the link-cut one — `system_reset` over the monitor, close the SSH master first, check `uptime` fell before trusting `vm-serial wait`, the `es_log.txt` read window before the next boot, and that the VM's virtio disk is not an SD card.

**Implementation size**: ~1,100–1,400 lines of Python in `tools/cloud-round-trip` (Kill ~250, Monitor ~50, shim/watcher staging ~80, 18 cells × ~40 ≈ 720, `litter_scan` ~120, message helpers ~60, registry/flags/`run_kill` ~100, `litter_scan`/`assert_message` calls in the four existing runners ~30), ~40 lines of guest-side `sh` (watcher, shim templates), one `tools/vm-walks/*.steps` file that must be frame-verified, one rule paragraph. About 2.5–3 developer-days including the VM time to watch each guard fire against the unfixed scripts (the harness's rule: a fixture's first commit carries its failing output). Optional and cheap: a device-less `tools/config-recovery-test` for `chksysconfig` in the shape of `wait-lock-test`, which needs `CFG_PATH` to become overridable (`chksysconfig:7` hard-codes it and sources `/etc/profile`).
