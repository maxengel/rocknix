# 2026-08-30 work log

## 00:35 UTC — Why the redirect cannot come back to us, and a CSS escape that shipped

**The redirect question, settled with evidence.** The maintainer asked why the
provider sends the phone to `localhost:53682` rather than the device's IP.
Checked on the device rather than reasoned about:

```
$ cloud_oauth info | sed -n 's/^PROVIDER=//p' | tr '&' '\n' | grep redirect
redirect_uri=http%3A%2F%2Flocalhost%3A53682%2F
```

That value is fixed by what rclone registered with Dropbox for its client id.
`rclone help flags | grep -i redirect` offers nothing — the `--*-auth-url`
flags change the *auth server*, not the redirect. The binary does carry
`urn:ietf:wg:oauth:2.0:oob` and `https://oauth.rclone.org/`, but neither is a
LAN address (the latter is rclone's own shim, which itself redirects to
`http://localhost:53682/`). And `192.168.1.81:8080` could never be registered:
it is different on every network. So the dead page stands — D-CLOUD-012 holds,
now with the check behind it rather than an argument.

**A CSS escape that survived a move.** Pulling the stylesheet into a `STYLE`
constant broke it. The page templates use `%`-formatting, so their inline CSS
had to write `%%`; moved into a constant that is substituted *as a value*
(`%(style)s`), the formatter never descends into it and `width:100%%` shipped
as literal CSS. Browsers discard an invalid declaration without complaint and
render the page, so three dead rules — both text inputs and every button —
were invisible.

The visible symptom was the one reported: a four-character PIN box rendering at
its default twenty-character width, which with 24px type and half-em letter
spacing overflows the card on a phone. Filed as blindspot 19, because the
general shape (escaping that was right where the text used to live) will
recur, and because the guard is specific: assert on the rendered output, not
on the fact that it rendered.

**Also:** the phone page is two numbered steps in the order they happen (sign
in, then paste), reversing the paste-box-first arrangement from yesterday —
that was right when the button was being mistaken for the whole job, and
numbering makes the natural order read better. And the handheld's sign-in page
gained a spacer under the group rule, which ComponentList draws flush against
whatever follows; everywhere else that is text with its own leading, here it
was a QR.
