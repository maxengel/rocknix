# Work log — 2026-08-27

## First working backup/restore round-trip on a device since January

Built `ROCKNIX-GENERIC_X64.x86_64-20260826` clean (631/631, no failures, ~2h49m)
and ran the full backup/restore round-trip in QEMU. Everything passed, and this
is the first image on which `backuptool backup` could execute at all — the
missing `zip` package had made the backup path dead since upstream dropped it
in January.

**backuptool, on the guest:**

- `zip` present and running (Info-ZIP 3.0), which was the whole point of the rebuild.
- `backuptool backup` completed: 16.4M, 227 entries, `unzip -t` OK.
- Credential stripping verified *in the archive*, not just in the code:
  `wifi.key=SUPERSECRET123` absent from the archived `system.cfg`;
  `cheevos_password` blanked to `""` while `cheevos_username` was kept, exactly
  as designed for the post-restore re-entry page.
- Archive rotation worked — the previous backup moved into `backup/archive/`.
- `backuptool restore` verified the archive, restored, set
  `.restore-finish-pending`, and rebooted. After the reboot all three planted
  settings held their backed-up values (`audio.preamp=77`,
  `display.brightness=33`, `video_fullscreen="false"`), having been mutated to
  11 / 99 / "true" beforehand. One-to-one match confirmed.

**cloud, via `tools/cloud-round-trip` over SSH:** all checks passed, including
the system-backup archive reaching the cloud and coming back byte-identical —
the phase-2 fix from the 26th, which had never run on a device — plus saves
round-tripping, the allowlist keeping excluded files out, and content
backup/restore.

**A test-design correction worth keeping.** My first round-trip attempt replaced
a 225-line OS-managed `system.cfg` with a 3-line synthetic file. After restore
and reboot the file had 225 lines again and my planted `wifi.ssid` was gone, which
looked like restore being undone. It was not: boot-time seeding regenerates keys
that are missing, and I had removed 222 of them. Re-running against *existing*
keys with distinctive values gave a clean, meaningful pass. A synthetic fixture
that does not resemble the real file tests the fixture, not the feature — the
same shape as blindspot 8.

Notes for the next session: the serial debug shell shares `ttyS0` with kernel
output, so commands are sent base64-encoded and decoded guest-side, with unique
BEG/END markers — multi-line and quoted scripts arrive mangled otherwise
(`/tmp/rkvm/ser.py`). Socket paths must stay short; `/tmp/rkser.sock` is fine
where a scratch-dir path is not. A separate two-day-old "ROCKNIX QA" VM is
holding port 10022, so this one runs on 10023.
