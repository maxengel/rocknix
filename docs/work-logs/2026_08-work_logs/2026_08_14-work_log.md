## Cloud setup: checklist page reworked into a gated wizard

- Tester feedback on the native page: it was a checklist, not a flow —
  confusing "1. Connect / Password / 2. Run" numbering, no how-to-connect
  instructions, "Password: Not Set" with no action, rclone-config text
  shown regardless of scenario, and nothing enforcing the mandatory steps.
- Now a three-step wizard; mandatory steps are *verified*, never
  skippable, only exitable (every gate offers EXIT SETUP):
  - Step 1 CONNECT: how to connect (same network, terminal, exact
    command, device IP, password) with fix-it rows when blocked — set a
    root password inline (`setrootpass`, same as SECURITY) or enable
    SSH. Gate: `cloud_setup --connected` must see an established
    inbound SSH session (read from `/proc/net/tcp*`, port 22/state 01 —
    no ss/netstat dependency).
  - Step 2 CONFIGURE: rclone-config instructions branched by scenario
    (first remote / add another / repair-modify with reconnect wording).
    Gate: `cloud_setup --check` must verify the remote. In add-another
    mode the gate diffs the remote list against wizard start and checks
    the remote that was actually added — a working pre-existing remote
    cannot wave the step through.
  - Step 3 DONE: confirmation + clearly optional immediate backup.
  - Entry point branches: no remotes → "SET UP YOUR FIRST REMOTE"
    wizard; otherwise a chooser (per-remote check / add / repair).
- Script contract (rclone e61fa9cac2): `--connected` (new gate),
  `--check [remote]` (named-remote verify), `--info` adds `SSH_UP` and
  `REMOTES`, drops the unconsumed `REMOTE`. Console flow unchanged.
- ES 5685f9552 (feature/cloud-sync-menu); wizard pages are sequential
  GuiSettings closed-then-pushed, so B always exits cleanly and gates
  are the only way forward. Pin bumped to 6cab46f92 (4c6d025af6).

## Round 2 (same day): parse bug + 4-step wizard with state marks

- Tester screenshot of the new step 1 showed the --info facts as one
  garbled row and false "no password"/"SSH disabled" states. Root
  cause: ES's `GetShOutput` strips each line's trailing newline and
  concatenates with no separator, so multi-line output parses as a
  single giant `IP=` value — this also explains the old checklist
  page's "Password: Not Set" while a password was set. Fixed by
  parsing via `ApiSystem::executeScriptLegacy` (public static
  per-line reader; `executeEnumerationScript` is protected and not
  callable from the wizard's free functions — caught by a one-object
  toolchain ninja compile before re-pinning).
- Flow restructured per feedback into four thin verified steps:
  1 device password (set inline if missing), 2 SSH service (enable if
  inactive), 3 connect (short how-to; gated on --connected), 4
  create/repair remote (numbered one-clause rows; gated on --check).
  Step names live in the subtitle; check-circle/warning glyphs mark
  state; GuiLoading spinners during checks; DEVICE IP hidden when the
  connection override is active (new OVERRIDE key in --info).
- Republished dev-generic_x64-20260814 (same-tag asset replacement,
  second time today — tester notified explicitly; sha256 is the
  disambiguator).

## Round 3 (into the 15th): CONTINUE crash was a use-after-free

- Tester: ES crashed after CONTINUE on step 1, with nothing useful in
  the logs. Root cause: gate handlers called s->close() (deletes the
  GuiSettings page) and then read their own captured std::strings to
  open the next step. close() destroys the executing row/button
  closure with its captures - use-after-free, segfault. Pre-existing
  codebase idiom (`delete s; ...` inside a row handler) survives only
  because it touches nothing captured afterwards; ours did.
  Fix: all step transitions go through cloudSetupAdvance(), which
  posts a copied closure to Window::postToUiThread - the copy is
  owned by the UI queue and survives the page teardown. Same
  treatment for the two-page close in the repair picker.
- Rest of the feedback round: CONTINUE / EXIT SETUP are bottom
  buttons (clearButtons replaces BACK; CONTINUE exists only once the
  step check passes); the password row is the action ("SET SSH
  PASSWORD" with state glyph -> view/change page; setrootpass applied
  only on real non-empty change, never on look-and-leave); subtitles
  read as actions ("CONFIRM DEVICE PASSWORD SETUP"); LOG(LogInfo)
  breadcrumbs at every step entry and gate verdict.
- One-object compile check before re-pinning (toolchain ninja against
  the unpacked package tree) caught nothing this time - and an earlier
  round it caught a protected-method call; cheap habit, keep it.
- Published dev-generic_x64-20260815 (fresh date tag - no same-tag
  replacement this round). ES pin 86d4d6030 (b0e74ecdbb). #26 updated.
