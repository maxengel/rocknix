# 2026-08-01 Work Log

## UTM boot failure: whitespace in AdditionalArguments

- Tester hit "qemu-x86_64-softmmu: -p: invalid option" booting the v5
  bundle: UTM splits its QEMU AdditionalArguments on whitespace, so the
  injected full SSH command (ssh -L ... -p 10022 ...) shattered into
  stray options. Generalizable rule: any value injected through UTM's
  argument list must be a single space-free token.
- Fix (419de5513d): fw_cfg key renamed to opt/org.rocknix.cloud_ssh_port
  carrying only the port number; the 095-cloud-ssh quirk validates it
  (digits, 1-65535) and assembles the full command guest-side, keeping
  tunnel + target in one place. Both launcher paths verified to emit no
  argument containing whitespace; quirk logic simulated standalone.
- Rebuilt (quirks+image stamps cleared), published
  dev-generic_x64-20260802, verified the shipped bundle's args and the
  in-image quirk, updated #26.

## Native ES page for cloud setup (console hop removed)

- Question examined: is there any reason setup must be a console screen?
  No - the on-device part is static text + wait + verify; the only truly
  interactive piece (rclone config) runs on the player's computer over
  SSH. Console hop replaced by a native GuiSettings page.
- cloud_setup gains --info (key=value connection facts: IP, SSH command
  incl. override, password, first remote) and --check (verify first
  remote; exit 0 working / 1 missing / 2 unreachable). The ES page
  consumes both, so UI and script share one source of truth. Console
  flow unchanged for non-UI contexts. (43962cd1eb, feature/cloud-saves)
- ES: GuiMenu::openCloudSetup - GuiLoading fetches --info off-thread;
  page shows connect/password/run rows, rclone checklist, CHECK CLOUD
  REMOTE action with three-way verdict dialog. Both setup entry points
  route to it. (06102aa36, feature/cloud-sync-menu; ES pin bumped to
  62ad0386c on test/qa-integration)
- The ssh:// QR code is gone with the console screen - it was a phone
  SSH-app convenience only; the flow targets a computer. If wanted
  later, ES has image-display components (GuiImageViewer precedent) but
  it needs a QR rasterizer in ES - not worth it now.
- Rebuilt with ES pin bump + rclone stamps cleared, republished
  dev-generic_x64-20260802; verified image ships cloud_setup --info and
  ES binary references it. #26 updated.
