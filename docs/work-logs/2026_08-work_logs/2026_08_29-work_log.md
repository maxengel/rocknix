# 2026-08-29 work log

## 01:10 UTC — Native cloud setup built, and the whole stack verified on a VM

Built P1 of #51 (native provider setup) and then verified the entire cloud
stack end to end on GENERIC_X64 against the WebDAV test backend, using a
remote **configured through the new UI** rather than by hand.

### Safety properties, demonstrated rather than reasoned about

These were all documented in `rclone-cloud-sync.md` as intent. None had been
shown to hold on a running device until now.

| Property | Evidence |
|---|---|
| ROMs/BIOS never reach the cloud | seeded `.sfc`, `.zip`, `scph1001.bin`, `gamelist.xml`, box art -> none present on the backend after backup |
| A save inside a ROM dir *is* synced | `snes/game.srm` uploaded |
| A `sync` restore does not delete the library | after restore every ROM/BIOS/artwork file still on disk - the `--delete-excluded` strip holds |
| Credentials never enter the archive | set `wifi.key="SECRET-WIFI-PASSWORD"`, then **0** occurrences in the 17 MB archive; `audio.preamp=42` preserved |
| `backuptool backup` works | archive created - the `zip` dependency fix (dead since January) confirmed |
| Both phases stay separate | `ROCKNIX/Saves/...` and `ROCKNIX/Backups/ROCKNIX_BACKUP.zip` |

Fresh-install defaults put `SYNCPATH_BACKUP="/ROCKNIX/Backups"` as a *sibling*
of `/ROCKNIX/Saves`, so our layout avoids the nesting trap upstream's `/GAMES`
default has.

Archive is **17 MB on a VM with no user data** - a concrete number for #45.

### Nine defects, and what actually found them

Only one was found by reading code. The rest needed the thing to run.

1. `GetShOutput` drops the last character of every chunk it reads, so
   multi-line output returns concatenated. The provider list became one
   bogus record - non-empty, so no error path fired; the group rendered
   empty and a search for "webdav" said "nothing matched". Added
   `GetShOutputLines` rather than changing a helper whose single-line
   callers want exactly the current behaviour.
2. TSV split used `removeEmptyEntries`, so any row with an empty column
   lost it and shifted left. Most options have no default, so nearly every
   form field vanished - the page looked finished and could do nothing.
3. Provider labels were rclone's documentation prose, truncated mid-word.
4. Options are gated on a sub-provider. koofr carries **three** separate
   options all named `password`; the form keyed by name, so it drew three
   identical rows writing to one value. s3 has 51 sub-providers and asked
   for IBM credentials regardless of vendor.
5. `local`, `memory`, `alias` and friends were offered as cloud providers.
   `local` in that list is a "backup" onto the same storage as the data.
6. Backend ids are not all shell-safe: `google cloud storage`,
   `google photos`.
7. `bool` options rendered as a text box wanting the word "true" typed in.
8. Options with a short list of suggestions rendered as free text - nobody
   guesses that generic WebDAV means the literal string `other`.
9. **The chosen list value never reached the config.** `addSaveFunc` runs
   from `GuiSettings::save()` at page close, but CREATE REMOTE builds its
   command while the page is open. The vendor was discarded *and the
   create reported success*, because WebDAV tolerates an empty vendor. On
   Sharepoint or Nextcloud that is the wrong dialect. Only reading back
   `rclone.conf` caught it - the dialog said it worked.

**The lesson worth keeping:** a passing end-to-end test certified #9 as
working. Verifying the *artifact* (what got written) rather than the
*outcome* (did it report success) is what found it. Same shape as the
`backup/*.zip` filter bug that shipped in four images: exit 0, SUCCESS
printed, nothing transferred.

### What made the loop cheap

`cloud_remote` is testable over SSH against a running VM in seconds; only
the ES half costs a build. Defects 4-8 were all found in one audit pass with
no build at all, by comparing real backend output against what the UI does
with it. Keep schema knowledge in the script and ES a renderer.

Also: enabling SSH on the VM (key over the serial console) turned a
slow screenshot-driven loop into a fast one. Do that first next time.
