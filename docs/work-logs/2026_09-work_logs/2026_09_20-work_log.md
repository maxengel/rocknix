## 18:35 UTC — The mechanism for the rule

`tools/fork-package-freshness` (`3834edb658`): enumerates the fork-introduced
packages from `git diff --diff-filter=A upstream/next next`, resolves each
latest release by host (GitHub, GNOME cache.json, GNU/savannah listings,
webkitgtk.org, ruby tags, rclone), compares commit pins with their default
branch, honours `# freshness: pinned -- <why>`, and exits 1 on BEHIND, 2 on
UNKNOWN. Proven to fire: brotli held back to 1.1.0 → BEHIND, exit 1. Its
first honest UNKNOWN was unifdef's home site timing out; the fix was a
GitHub fallback for that one host, not a softer exit code. Registered in
`fork-workflow.md` ("When to merge up"), the tool index, and the pre-push
guard.

## 18:40 UTC — WebKit 2.54 twice: the option graph, not the option

Run 7 died at 18:32 in WebCore's precompiled header, `gst/gst.h: No such
file`, with video and Web Audio already off. `USE_GSTREAMER` is a public
option (default ON) that four features depend on through
`WEBKIT_OPTION_DEPEND`: video, Web Audio, speech synthesis, and WebCodecs —
and the GTK port defaults WebCodecs ON. Turning off the two I could name left
the third holding GStreamer in the build while the include path for it was
gone. `-DUSE_GSTREAMER=OFF` is the switch the graph hangs off; WebKit takes
the four down with it (`ef905ccc2e`). Run 8 launched 18:35.

Two attempts on one failure, not three, and the second read the cmake
dependency file rather than the next symptom — but the first fix chose the
symptom's names (VIDEO, WEB_AUDIO) over the mechanism's (USE_GSTREAMER). The
question that would have skipped run 7: *what sets the thing the error is
about?* — not *which feature sounds like video?*

The image keeps GStreamer regardless: qt6, gst-plugins-good and gst-libav
depend on it. webkitgtk's `gstreamer gst-plugins-base` dependency line is
now ordering only, left in place.

## 18:50 UTC — WebKit 2.54: the fourth failure is the answer, so 2.52.6 ships

Run 8 fell in WebDriver (an undeclared log channel; WebDriver off,
`e39fc7f68a`). Run 9 fell in WebCore's JS bindings:
`JSHTMLMediaElementCustom.cpp` is compiled unconditionally and needs the
binding only `ENABLE_VIDEO` generates. That is the model, finally: **2.54.0
does not build with video off**, video needs `gstreamer-mpegts` and
`gstreamer-gl`, and the image builds neither. Four failures, three fixes;
the stop line said the fourth is a revert, and it was (`77e7e97515`, the
recipe that shipped builds 11-16), with `# freshness: pinned -- ... (#228)`
so the sweep passes for a stated reason. #228 holds the three ways forward
(gst-plugins-bad's mpegts plus GL in gst-plugins-base; a WebKit patch or
2.54.x; stay on 2.52.x). Run 10 launched 18:47.

What the three fixes cost: about thirty minutes of build time, and they
taught the option graph. What they would have cost without the stop line
is the evening. The lesson for the freshness rule itself: a bump that
changes a large package's *defaults* (WebKit 2.54 turned on WebCodecs and
made video's GStreamer libraries hard) is not a version bump, it is a
configuration change, and it wants the VM build before anything else — which
is the order this ran in, and why the handhelds never saw it.
