## 02:05 UTC — Keeping the truth of device actions: a rule and a tool (D-QA-025)

The maintainer asked what to add to the instruction files so the harness keeps track of
the truth behind claims about device behaviour. Two things. The rule
(`engineering-practices.md` § A device's state is read from the device): before saying
what did or did not happen on a device, read the device's own record -- the previous
boot's journal, its ssh logins, the unit log, the boot id -- and treat the transcript's
tool result as one witness; when they disagree the device wins and the disagreement is
reported; answer "did you do X" with evidence, not memory; correct every place a wrong
statement landed, in the same session. The tool (`tools/device-act`, fork-only, in the
pre-push guard's personal list and `fork-workflow.md`): every state-changing act on a
device runs through it, and it appends BEGIN and END lines with the device's boot id
before and after to `/workspace/artifacts/rocknix-device-actions.log`, outside the repo
and outside any session scratch -- a changed boot id is a reboot whatever anyone
remembers. Self-tested on guest a with a read-only command.

## 04:05 UTC — #175 found and fixed: the settings page's save wrote a failed sign-in as "off"

The write was `GuiRetroAchievementsSettings.cpp:281` -- the page's save function wrote
`global.retroachievements` from a `newState` that `:275` forced false whenever
`RetroAchievements::testAccount` failed, and the test re-ran whenever the token was empty
(upstream's `f747a4d277` over `2c7c79bf2f`). The boot login never writes the switch, so the
flip took two things: a boot whose sign-in ran before the network, and the settings page
closed while still offline -- reproduced on RC `31253072d6` with `inotifyd` watching the
settings directory (ES's own `system.cfg.tmp` then `.backup.tmp` at the moment of the
UNABLE TO ACTIVATE dialog; `=0` after; the MAIN MENU rebuilt without the entry). Fix in ES
`461e14305`: the save writes the player's choice only; `testAccount` tells a refusal from
an unreachable server; refused -> "RETROACHIEVEMENTS DIDN'T ACCEPT YOUR SIGN-IN: <why>" with
the switch left on; unreachable after a change -> "COULDN'T REACH RETROACHIEVEMENTS TO SIGN
YOU IN. RETROACHIEVEMENTS STAYS ON. IT'LL SIGN IN WHEN YOU'RE ONLINE."; unreachable with
nothing changed -> a log line; and `NetworkThread` re-runs the token check when the network
comes up after a non-refusal failure (posted to the UI thread -- a direct reset inside the
watcher's notify would deadlock). French for the three strings. Two reading lessons: ES's
file log is batched, so `es_log.txt` read mid-boot may lack a line that was logged (read
`es_log.0.txt` after the next boot); and the guest filter removes `qa-accounts`' own
"password: empty" report line -- read its exit code. The pin moves to `461e14305`; the
image waits for #176.
