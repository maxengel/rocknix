## 02:30 UTC — #212: a game's images are cached with its achievements, proven on guest d

- Maintainer: *"Let's chase the cache now [...] Those actions are linked so that whenever we cache the achievements, we cache the images for the achievements."* Built as `raofflineproxy-cache-images` plus a `raofflineproxy-ctl images` verb, run at the end of a scan and of a top-up that cached anything (`4a0b094022`).
- **The gap was real and measured first**: the RG SP held 494 cached set rows referencing 56,111 image paths with **956 missing** across 123 games; guest d held 566 of 9,648. The cause is upstream's design plus our bound: the client queues a set's images on a four-worker pool and cancels what has not started at exit, and the scan gives that pool one global 120 s grace (#188's fix for a helper held 83 s past DONE). A library's scan queues tens of thousands, so most are dropped -- and a miss is 404 at once while offline (patch 012).
- **Proven on guest d against its real store**: 566 found; a 5 s ceiling fetched 40 and reported `still missing 522`, exit 1; a full run fetched 522 and left 0; a second run `0 missing`, `NOTHING_MISSING`, exit 0; the verb through the staged ctl the same. With the store filled the proxy answers a cached badge and icon 200 with bytes and an uncached path 404 at once. Idempotent by file existence, resumable because nothing marks a game done but its files.
- **A correction I owed #211 first**: I checked the device's store before writing any code, and Bubble Bobble was missing **one** image -- `Images/086846.png`, the game icon -- while all 182 badges were present and served. So the crash was not preceded by a failed badge fetch, the 404 theory is dead, and the issue says so. The crash stays unexplained pending a dump on the VM and a second routed achievement.
- **A sharp edge noted, not changed**: `store_only_requested` matches the header only in its exact and all-lower spellings, so a client that capitalises it as urllib does (`X-ra-store-only`) silently takes the fetch path. It cost me one wrong reading while testing; the interface sends the exact spelling, so no player is affected. Recorded on #212 for the next time that patch is touched.
