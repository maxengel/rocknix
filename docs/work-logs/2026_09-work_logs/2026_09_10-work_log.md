## 20:26 UTC — #104: the survey found half of it already in the image

Maintainer: "let's proceed with 104, and 105 can include everything you
mention, and we can go in that order."

The survey came before the design, and changed it. Upstream ships
`var-log.mount` -- `/storage/.cache/log` bound over `/var/log`, the journal
directory made by `storage-log.service`, pulled in by the journal flush --
gated on a debugging marker; the H700 kernel has `CONFIG_PSTORE=y` with no
backend and the Allwinner watchdog driver with its node in the DT;
`systemd-pstore` is installed and would archive into tmpfs. So the first two
boxes became one condition line and two journald limits, and the crash store
became a kernel patch plus three config lines rather than a design. That is
blindspot 37: #102's watcher rebuilt over SSH what the image had switched
off.

Decisions, each with its reason in the register: on by default with an
opt-out marker (D-SYS-001); 15 s runtime watchdog because the Allwinner one
counts to 16 and a refused timeout means no watchdog at all, reboot watchdog
off because that same ceiling would reset a device mid-sync at shutdown
(D-SYS-002); lockup and hung-task panic, `panic=10`, `panic_on_oops` left
alone since the journal now catches an oops (D-SYS-003); ramoops at
`0x4F000000` in the SoC dtsi after mapping every address U-Boot uses on
H700 -- kernel 0x40080000, U-Boot 0x4A000000, FDT 0x4FA00000, SPL stack
0x4FE00000, ramdisk 0x4FF00000, and the top of RAM where U-Boot relocates
(D-SYS-004); a five-minute state page and a `collect` archive that is the
first thing done to a misbehaving device (D-SYS-005). Parked: a userspace
watchdog, wanted only if a frozen device ever shows a healthy kernel
(D-SYS-006).

The hang policy went into `/usr/lib/sysctl.d`, not `/usr/config/sysctl.d`:
the latter reaches `/storage` through `userconfig-setup` after
`systemd-sysctl` has already run, so it would apply from the second boot
after an update. A sysctl that must hold on the first boot is image-level.

Both handhelds were offline, which is the right way round: the VM proves it
first, and the VM got the same features -- pstore over UEFI variables,
QEMU's i6300esb watchdog in the profile -- so it can. The one thing it
cannot prove is whether H700 DRAM keeps the ramoops region across the SoC's
own reset; that is a deliberate crash of somebody's device and waits for a
yes.
