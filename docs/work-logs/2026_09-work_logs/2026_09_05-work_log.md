## 00:01 UTC — Skraper is the interim scraping route (D-QA-004)

The maintainer asked why fork builds cannot use screenscraper.fr, since the
scrapers that remain (IGDB, ArcadeDB) are poor. The answer is a credential:
ES sends ScreenScraper a developer id and password on every request
(`SCREENSCRAPER_DEV_LOGIN`, compiled in), upstream's lives in CI secrets, and
borrowing it would bill our scraping to ROCKNIX's quota under their name. Our
own id is a registration with ScreenScraper, in the maintainer's name.

Skraper sidesteps that: it carries its own developer id and uses the player's
account. Checked skraper.net — free, closed source, GUI only, Windows/Linux
(mono)/macOS (WINE), writes RecalBox-layout gamelists our ES reads. Checked
our side — ROCKNIX shares `/storage/roms` over SMB, and
`cloud_content_backup` carries gamelist.xml and media (only saves are
excluded), so one scrape propagates through the content tier. Maintainer:
"a good interim route." Recorded as D-QA-004 refining D-QA-003; the stash's
"scraper route" open question is closed.

Practical notes for the first run: RecalBox output profile; scrape with ES
idle and reload gamelists afterwards; expect a slow first pass on a free
ScreenScraper tier; it does not run on serval (no desktop).

**Does Skraper have a CLI? (asked 00:00 UTC) — No, not any more.** Verified
against the release itself rather than the docs: downloaded
`Skraper-1.4.1.7z` (25 MB, built 2026-08-04) and listed it — 104 files, one
executable, `SkraperUI.exe`, plus `SkraperLibrary2.dll`. No `Skraper.exe`. The
bundled release notes from 1.2 through 1.4.1 never mention a command-line,
silent or batch mode. The Linux installer's generated `run.sh` still carries an
`elif [ -f ./Skraper.exe ]` branch — a vestige of the 2018 command-line tool
(`Skraper.exe <romdir> "<system>" -output=… -ssu= -ssp=`) that the GUI grew out
of; the Recalbox forum thread that documented it now redirects to their wiki.
So the interim route is a GUI on a machine with a desktop. If unattended
scraping ever matters, Skyscraper (open source, CLI, carries its own
ScreenScraper developer credential, writes ES gamelists) is the tool to
evaluate, and it would run on serval.

## 02:39 UTC — Locking down the two exits: the image and git (D-INFRA-006, blindspot 26)

Maintainer: personal ScreenScraper and RetroAchievements credentials for local

- **Through a build.** The four keys are compiled into the ES binary, so a
  personal key in `~/.ROCKNIX/options` ships inside every image built while it
  is set — fine on the maintainer's devices, a leak in a public prerelease.

  `.env` is 0600 and removed after the run, and the ES recipe prints
  `USING: <key> (set)` instead of the value. The leaked `devices/.env` is gone.
- **Through git.** Both public repos already had GitHub secret scanning and
  push protection on, and neither tree holds a secret-shaped value. Push
  protection knows GitHub's token catalogue, not a ScreenScraper dev password
  or an RA key, so `.githooks/pre-push` now scans **every** pushed branch for
  credential-shaped values at the pushed tip, redacts them in the message and
  refuses; angle-bracket placeholders pass. Proven: real value → rc 1,
  placeholder → rc 0, incremental range with an RA key → rc 1, zero false
  positives across the tracked tree.
- **The guard that was not running.** `core.hooksPath` still pointed at

  `tools/fork-worktree list|sync` warn when the path is unset, relative, or

`~/.ROCKNIX/options` created 0600 with commented placeholders and the warning
