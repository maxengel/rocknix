## 01:40 UTC — The vocabulary sweep (#73, D-UI-022, D-CLOUD-040)

Started from one confusion — two config keys that sounded like different
payloads and were two directions of one transfer — and ended as a rename of
every name cloud sync uses, because the audit (`docs/cloud-vocabulary-audit.md`)
found the archive we called a *system backup* held settings and nothing else.

**What changed, both repos.** Distribution `24dce33f23` + `b1e8d1f646`;
EmulationStation `d161afb2b`, merged as `2045c4d33c` on `test/qa-integration`.
Two verbs, the noun says what, the destination says where. Config keys renamed
to say tier and side; `cloud_sync_helper` carries a customised value across
once and moves the settings rows' last-run stamps; `RESTOREPATH` removed and
refused if still set differently; the archive is `<date>-ROCKNIX_SETTINGS.tar.gz`
with all three earlier names still read; the wizard document reaches rev 5.

**Three things learned doing it.**

- **A naive replace would have renamed the main menu.** Four `"SYSTEM SETTINGS"`
  strings in `GuiMenu.cpp`; one is the cloud tier, one is the main-menu entry,
  one its page title, and one is the *per-emulated-system* group on the game
  settings page. My survey called two of them cloud tiers; reading the context
  before editing caught the second. Grep counts locate a string, they do not
  classify it.
- **Read-old-if-new-absent is not enough when the helper appends defaults.**
  The append loop adds any missing key with the shipped default, so a device
  that had customised `SYNCPATH` would have gained a `SAVES_REMOTE` pointing at
  `/ROCKNIX/Saves` and silently switched folders — the exact trap
  `upgrade-and-install.md` names. The migration runs before the append and
  copies the value, proved by a harness: `/Custom/Saves` survives, the content
  folder derives beside it, and a second run adds nothing.
- **A revision note is a historical record.** A blind `rev 4 → rev 5` replace
  rewrote the *rev 3* summary to say what rev 5 decided. Restored, and rev 5
  added as its own block. Version markers name the past; edit the present.

**Two findings for later, not fixed here.** `cloud_setup --set-syncpath` keeps
the settings-backup folder at `<new>/backup`, *inside* the saves folder — the
layout `cloud_migrate_layout` exists to move people off. And
`BACKUPFILE_BACKUP_OPTION` / `BACKUPFILE_RESTORE_OPTION` keep their names: not
in the audit's collision set, and clear enough about what they gate.

**Next.** Merge to `next`, build H700, deploy to the RG35XX SP, and watch the
upgrade path: the migrated keys, the settings rows' stamps, and every renamed
string on screen. Then the rocknix.org docs PR the hard gate requires.
