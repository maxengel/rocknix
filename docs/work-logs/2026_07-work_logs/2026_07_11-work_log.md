the cross-host machine profile. The remaining defect was specifically the **cursor graphic**

output orientation. ROCKNIX already uses wlroots' software-cursor workaround for NVIDIA, and
an old QEMU quirk incorrectly applied it to unused `weston.service`; active Sway did not receive
it.

Fixed `111-sway-init` to set `WLR_NO_HARDWARE_CURSORS=1` only for virtual DRM connectors
(`Virtual-*`). A rebuilt GENERIC_X64 image full-booted with Sway active, and
`/var/log/sway.log` confirmed `Loading WLR_NO_HARDWARE_CURSORS option: 1`. This leaves pointer
coordinates and display transforms unchanged while compositing the cursor in the correctly
oriented primary plane.
