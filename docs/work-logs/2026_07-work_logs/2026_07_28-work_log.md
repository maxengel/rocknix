## Tester feedback: QR still dead, guest showed 10.0.x

- Root cause chain: placeholder edit is real friction; tester didn't do it,
  fallback correctly showed the guest's own (unreachable) NAT address.
- Investigated alternatives before adding tooling:
  - iOS Safari REFUSES credentials-in-URL (since iOS 11) — the QR's
    user:pass@ userinfo is Android-only sugar; the login_token query param
    is what actually signs iPhones in (it's base64(user:pass), handled by
    rclone's GUI, not the browser). Keep both.
  - In-guest host discovery is impossible by construction: user-mode NAT
    exposes the host only as 10.0.2.2; no query returns its LAN address.
  - VirtualBox is a dead end: no x86_64 guests on Apple-silicon hosts
    (virtualizer, not emulator), and its NAT has the same information
    boundary anyway.

## One-click phone-QR helper for macOS (set-up-phone-qr.command)

- Bundle zip now carries an executable .command next to the .utm: detects
  the Mac's LAN address (route -n get default + ipconfig getifaddr),
  rewrites the fw_cfg argument in config.plist via BSD sed, validates with
  plutil. Idempotent; re-run after network changes.
- Template lives in the VM dir; build fills @FWCFG_NAME@/@HOST_PORT@ from
  profile.json so tooling can't drift from the profile. Exec bit set via
  ZipInfo external_attr (0o100755<<16) — verified to survive unzip, and
  macOS Archive Utility honors it. Gatekeeper: first run right-click>Open.
- Platform matrix documented in the VM README: Linux automatic (launcher),
  macOS one double-click, Windows expected via WSL2 QEMU + Linux launcher
  (plus netsh portproxy or mirrored networking) — deferred until a Windows
  tester exists.
- Guest image unchanged (host-side tooling only): republished the same
  release with a refreshed utm.zip; sha256 asset updated alongside.
