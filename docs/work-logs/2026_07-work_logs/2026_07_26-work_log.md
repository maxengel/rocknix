## UTM boot-hang triage: bridged-by-default reverted (profile v3)

- Reported: 20260726 UTM bundle "never boots, just spins" + looked ~100MB
  smaller. Verified image healthy by booting the published qcow2 under KVM
  (kernel 5s, sway+ES up, storage resized, cloud tools present); release
  asset sizes identical across days -> size delta was a truncated download.
- Root cause of the hang: rev 4 defaulted the UTM bundle to Bridged vmnet,
  which fails/hangs on many macOS Wi-Fi hosts. Reverted default to
  Shared/NAT (forwards: SSH loopback, web GUI LAN-bound); Bridged is a
  documented one-click opt-in. Also earlier: per-bundle UUID/MAC fix.
- Lesson: VM profile changes need a boot check on the weakest host config
  before release; NAT-default + opt-in bridged is the safe posture.

## UTM bridged hang: root cause confirmed from user log

- Unified log showed `SWIFT TASK CONTINUATION MISUSE: start(launcher:interface:)
  leaked its continuation` — UTM awaits macOS vmnet bridge creation forever
  when the interface can't be bridged; manifests as an infinite spinner.
- Not fixable from our artifacts (NIC model irrelevant); mitigations: explicit
  en0 interface, UTM update, else NAT + http://<mac-ip>:15572. Fingerprint
  documented in the VM README. Validates the NAT-default decision.
