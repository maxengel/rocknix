## The three judgement rows

- **F1-res (run 2's case 2: "an unrecorded 1280x800 became 640x480").** That was the **quirk on 4234be0b6b**, not the
  script's setup: the setup removes the record for that case (`rm -f $REC`), and 4234be0b6b's quirk took an unrecorded
  value by name (`[ ! -f RECORD ] && { X,Y = mode || X,Y = 1280,800 }`). afe32f0afd dropped the 1280x800 clause: an
  unrecorded value is taken only when it equals this boot's size. On 1b0d233657 case 2 is **left at 1280x800** (run 2
  and run 3). Run 2's other FAIL ("the record now says 640x480") was the script reading the old record format:
  this build writes `surface=640x480`; the script reads both forms now. The "no record, equal to this boot's size"
  clause cannot be told apart on a 640x480 guest (640x480 is also the shipped value).
- **D-pl059.** Run 2's `found=0 ... why=NO_GAMES_FOUND` came from the guest, not the change: `recovery/snes/` holds
  cheevosHash entries from A-pl001's and E2-pl014's files, so snes is an indexed system and the walk leaves its new files
  to the index. In snesh/ the stamp reads `1790592455 0 scan cached=0 skipped=10 ready=4 limit=0 indexed=0 errors=0
  added=0 truncated=1` -- rc 0, no why, no TOOK_TOO_LONG (that why belongs to an image pass with no time left, which
  this scan did not reach). The cursor was proposed (`cursor_saved=1`), kept as `scan-cursor` = `qa307-g10.sfc` only
  after the jobs ran, and no `scan-cursor.next` was left. **The item holds.**
- **E2-pl061.** Rewritten for f4c9549ba: the proof is the refusal -- the spinner at 07:00:59, the Warning line at
  07:01:09 (10 s), no game for 15 s, the box `frames/E2-pl061-refused.png`, then the capture's own post ran the exit
  sync and the next press started the game. Run 2's 0 PASS was the FINISH RESTORE PROCESS page from run 2's PL-029:
