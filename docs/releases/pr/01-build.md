Title: build: recipes fetch nothing at configure and forward no secrets

A package now fails to configure instead of quietly cloning a dependency the tree does not carry. I found this the hard way: pango had been building its own cairo from git master for three months, over the pinned one, and every image I built shipped it without anyone noticing. mangohud and gamescope were fetching their Vulkan headers, glm and stb the same way. The build now refuses meson's downloads, and those three packages carry the trees they need as pinned, hash-checked sources. Along the way I fixed a handful of small recipe problems I met: libyaml's host dependency on ccache, cairo moved to 1.18.4, nvtop's backends gated on the drivers that are built, the aarch64 guards the recent cleanup dropped on five standalone emulators, libsamplerate on x86_64, and an aarch64-only flag in ppsspp-lr that was being stripped after the patches rather than before.

The docker recipe also stops forwarding anything that looks like a credential from my shell into the container, and writes its .env file fresh and owner-only. I had been leaking my own tokens into a world-readable file for weeks.

I ran the package check on every recipe touched, built mangohud and gamescope on a cold SM8550 root with the download guard on, and built full images for H700, SM8550 and an x86_64 virtual machine. The guard was seen to fire on the pango case before the fix and pass after it, and the secret filter was checked against a made-up variable that did not reach .env. No package version moves except cairo, no device options change, and nothing here is visible to a player. No kernel, bootloader or device tree changes. This one stands on its own; the rest of the series builds on it.
