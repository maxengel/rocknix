Title: GENERIC_X64: a virtual machine build target for QA on a desktop

This adds a build target that runs ROCKNIX as a QEMU or VirtualBox guest: the same busybox, the same scripts, the same EmulationStation binary and the same 640x480 panel size as a handheld, with software GL, a serial root shell on the virtual machine only, and per-device emulator configurations that name no handheld's hardware. It is where I proved every change in this series before a handheld saw it, and I would like other people to be able to do the same.

It carries the device directory (options, the kernel config, the VM launcher and its profile), the quirks for the device and for QEMU, the x86_64 initramfs, syslinux and installer changes, x86_64 fixes in gcc, libplacebo, mupen64plus and gliden64, per-device configurations for the standalone emulators and RetroArch, a few image-script changes (the release directory pruned whole), a graphics fix so a device's LLVM choice survives the driver reset, and the device's emulator list. That last file also carries the core-pins map the saves change reads, because it is one file.

I tested it by booting the image headless under QEMU and running my whole QA on it: the cloud round trip against WebDAV, S3, SFTP, SMB and FTP backends, a script harness under the image's own busybox, walks of the screens at 640x480, and an upgrade rehearsal from the previous image. Those tools stay in my fork; upstream gets the device. No handheld's options or kernel change, and no shared package changes behaviour on aarch64 beyond the x86_64 branches named above. The kernel config, initramfs and syslinux here are x86_64's only. It needs the build change before it, so the new device builds without a download.
