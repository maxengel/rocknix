Title: rocknix: saved Wi-Fi networks, and a device name mDNS answers to

NETWORK SETTINGS now reads the truth from NetworkManager instead of a setting that could disagree with it. WI-FI NETWORK names the network in use, the picker lists what is around with the ones you have joined marked SAVED and the current one CONNECTED, a saved network can be joined with the key NetworkManager holds or forgotten, and MANAGE SAVED NETWORKS lists everything kept. wifictl gains current, saved, join and forget, keeps a typed key in the network's profile, brings a saved profile up as it is, and never deletes one to reconnect. The device's name is owned by one setting, NetworkManager leaves it alone, and the mDNS responder comes up after the device has its name, so name.local answers.

It carries wifictl, the NetworkManager configuration, avahi's unit and recipe, the network base setup and its unit, and the network services fragment, whose state is now reset before each daemon fragment runs.

I tested the saved-first connect with three harness cases under the image's busybox, the picker's press on a saved network on the virtual machine with a stand-in wifictl (CONNECT, FORGET and CANCEL, the forget made once, the list re-read), and the hostname with two names on two guests. On my RG35XX SP I forgot a saved network from MANAGE SAVED NETWORKS and joined it again. The access-point and netplay paths still use iwctl on the interface side, and Bluetooth is untouched. No kernel, bootloader or device tree changes. It depends on the settings change before it for the shared settings functions.
