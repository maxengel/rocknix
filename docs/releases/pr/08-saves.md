Title: rclone: saves synced on their own, every save recorded, content tiers

Saves now sync at startup and after every game, bounded (a 90-second ceiling, a stall watched through a fifo) and visible (a card that ends COMPLETED, COULDN'T FINISH with a reason, or SKIPPED for no network or a game started). A launch waits for a sync it can see instead of cancelling it. Every game exit is recorded in a per-device manifest, each save version by the hash of its bytes and the emulator, core and device that wrote it, taken from a staged copy and never the live file; the boot pass re-hashes what the manifest claims and adopts nothing. What a transfer replaces is set aside for one cycle. ROMs and BIOS and the scraper's content back up and restore a system at a time, copy-only, and one action matches the device to the cloud after showing what it would delete. On a WebDAV server that compares by size alone, a save that changed but kept its size now moves, judged against its upload time. The launcher's state-file contract lets the save-state manager and RetroArch agree on which state a launch loads.

It carries the backup, restore, capture, content backup and restore, sync helper, saves root, layout migration and log scrub scripts (the last masks credentials earlier builds had logged), the configuration and its defaults, the allowlist (databases excluded first, the standalone N64 saves included), the boot autostart, runemu.sh (the platform and save-state flags by argument, the exit status returned), input_sense (the exit hotkey's press marked), the save-state configuration, and three RetroArch patches: one poster at a time on the threaded video wrapper, a posted command run once, and the Auto slot kept across a content load.

I tested it with a cloud round trip on the virtual machine against WebDAV, S3, SFTP, SMB and FTP backends, with the link cut at seven points mid-run; the size-only case with a two-second wait; the capture's own harness under the image's busybox; the upgrade rehearsal from the previous image; and my own play on an RG35XX SP, offline and back. The provider setup is the change before this; the pages are the interface change's. No kernel, bootloader or device tree changes. It depends on the cloud setup change, whose rclone recipe installs these scripts, and on the RetroAchievements change for setsettings.sh.
