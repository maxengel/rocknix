Title: rocknix: persistent logs, a watchdog and a crash store on handhelds

When a handheld misbehaved, the reboot that followed used to take the evidence with it: /var/log was tmpfs and the journal went with it. Logs now persist under /storage, a hardware watchdog restarts a hung device and records that it did, kernel panics land in pstore, and a bounded ring of core dumps is kept so the next crash can be read. One script collects all of it into an archive on a timer, and another arms the core store when asked.

It carries the two scripts and their units, busybox's sysctl and mount units (the storage log, the /var/log mount, the hang policy, the coredump pattern), systemd's watchdog and pstore configuration and tmpfiles, powerstate's start order and its no-battery case, and the rocknix package recipe that installs the scripts. That recipe is shared with the settings change that follows, which is why chksysconfig's unit and the bootloader updater gate appear here too.

I tested it on an RG35XX SP across a power cycle: the previous boot's journal was readable after it, an EmulationStation crash left its backtrace in the journal, and a core was kept under /storage/.cache/log/cores and read on my desk. On the virtual machine I ran the same units and a harness that runs every shell script under the image's own busybox. Nothing changes about what is logged, only where it lives and for how long. On H700 the kernel config gains pstore and the ramoops driver, and a device tree patch reserves the memory ramoops writes to; other devices are unchanged and get pstore only where their kernel already offers it. It builds on the build change before it.
