## `BUILD_ID`

```
scripts/image:54-58   if [ -n "${CUSTOM_GIT_HASH}" ]; then GIT_HASH="${CUSTOM_GIT_HASH}"; else GIT_HASH=$(git rev-parse HEAD); fi
scripts/image:160     BUILD_ID="${GIT_HASH}"
scripts/image:161     BUILD_BRANCH="$(git branch --show-current)"
scripts/image:162     BUILD_DATE="${BUILD_DATE}"
```

`BUILD_ID` is the full commit of the checkout `scripts/image` runs in (the build worktree's head at sync time, not the pin of any package), or `CUSTOM_GIT_HASH` when set. It carries **no timestamp**: the date lives in `OS_VERSION` (`distributions/ROCKNIX/version:4`, `$(date +%Y%m%d)` at build time), `BUILD_DATE` (`:162`, from the environment) and `/etc/release` (`:150`, `<device>.<arch>-<OS_VERSION>`). Its **host dependence** is the checkout: the same commit built in two worktrees carries the same `BUILD_ID` and a different `BUILD_BRANCH` (`worktrees.md`), and a detached checkout ships an empty branch. RC2's shipped values, read from the H700 image: `BUILD_ID="69e6039f8fdbf971d3e6b694537f250036fdcd98"`, `BUILD_BRANCH="build/devices"`, `BUILD_DATE="Tue Sep 29 22:19:37 UTC 2026"`, `OS_VERSION="20260929"`, `OS_BUILD="community"`.

## What the read changes in the plan

1. **Branch B.** P3 rehearses the documented manual path on the RG35XX SP; P4 ships a fork-aware updater that never queries ROCKNIX's endpoint (`p0-updater.md`).
2. **The migration tar's name.** The RC2 init refuses an update file whose name lacks `ROCKNIX` (`init:882-889`, a reboot with "Unsupported operating system update"), so the RC2 → 0.0.1 tar carries `ROCKNIX` in its file name (an `IMAGE_SUFFIX`, `scripts/image:110-111`, or a renamed copy staged by the procedure); from 0.0.1 on, the check reads the new name.
3. **The build roots.** P2's cold GENERIC_X64 root is the right call; for the three device roots P2b chooses between moving the roots (then cleaning `busybox`, `installer`, `linux`) and cold builds, and records which.
4. **One open question for the owner**: the statistics report (`rocknix-report-stats`) would count every 0.0.1 device in ROCKNIX's install statistics; disabling its timer is a one-line change with no other consumer (class 3, KEEP until a yes).
