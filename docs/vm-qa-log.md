# VM QA log

One row per VM test cycle, so the next cycle starts from the last one rather
than from zero. The ritual that fills it is `generic-x64-vm-testing.md`
§ "After every VM cycle"; the narrative stays in the work logs. A cycle is a
built image driven in the GENERIC_X64 VM against a fixture, with frames read
and the endpoint inspected.

The last three columns are `tools/time-to-play`'s headline numbers for that
image, in seconds, as the median of the run's repeats (#135, D-CLOUD-098):
the press on a game to the game's first frame; `execute_kill` to the exit
sync's `last-sync-exit` stamp; and `execute_kill` to the NEXT game's first
frame with the exit sync in flight. `tools/vm-qa` runs the cell's bounded
form on every image and writes its own table at the foot of the run's
report, where the startup sync, the offline benchmark (D-CLOUD-112) and the
bounds (D-CLOUD-111) are too. **No budget row exists yet**, so a number here
is a record, not a gate; the rows are proposed from the measurement and the
maintainer sets them (D-CLOUD-116).
